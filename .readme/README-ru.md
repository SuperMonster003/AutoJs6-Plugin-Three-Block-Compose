### Введение

******

3-Block Compose - плагин отрисовки интерфейса для AutoJs6. Сценарии объявляют интерфейсы через `compose` / `$compose` хоста, а плагин отрисовывает их внутри его процесса с Jetpack Compose и Material 3. Предварительная версия поддерживает активности `"ui";` и плавающие окна сценариев без UI.

В плагин встроены визуальный дизайнер и галерея компонентов: при открытии из лаунчера вы попадаете на главный экран дизайнера, где проекты скриптов создаются или импортируются и редактируются на реальном рендерере, а галерея показывает превью и примеры скриптов для каждого компонента; интерфейсы скриптов по-прежнему отрисовываются в процессе хоста. Хост обнаруживает плагин через службу INFO, читает версию и сведения о совместимости и создаёт фабрику рендерера в своём процессе по контракту (`org.autojs.plugin.compose.api`).

### Текущее состояние

******

1.9.0 - текущий публичный выпуск (GitHub Release, внесен в официальный индекс плагинов). Требуется сборка AutoJs6 6.8.0 (5322) или новее с новой идентичностью 3-Block Compose (коммит хоста f12665ffde или новее); на момент публикации AutoJs6 6.8.0 еще не вышел официально, поэтому нужна сборка AutoJs6, содержащая этот коммит. Пункт меню редактора AutoJs6 "Открыть в дизайнере 3-Block Compose" требует сборку после коммита хоста db7e6a1734, а TSX-проектам дизайнера нужен TypeScript Engine 0.7.0, а предпросмотру макета проектов UI (XML) нужна сборка, содержащая службу предпросмотра (коммит хоста 306a8f7834 или новее). Плагин включает страницы UI, плавающие окна, визуальный дизайнер (проекты Compose и UI), пять примеров, справочник API, страницу руководства по дизайнеру и объявления TypeScript. Проверенный охват совместимости и производительности записан в дорожной карте. Значки используют финальную графику сопровождающего. С 1.7.0 интерактивный предпросмотр проектов UI (XML) заставляет AutoJs6 по-настоящему выполнять весь скрипт; нужна сборка AutoJs6 с контрактом предпросмотра v2 (коммит хоста 4c332c2053 или новее) и Android 13 или новее. С 1.8.0 проекты UI могут хранить макеты в XML-файлах и становиться проектами-папками: предпросмотрам с файлами проекта нужен контракт предпросмотра v3 (коммит хоста 9df0a154b или новее), а запуску и импорту проектов-папок в AutoJs6 нужен коммит хоста faf412ef7 или новее. С 1.9.0 диалогам, кнопке Назад, паузе и возобновлению и пределу занятости главного потока в интерактивном предпросмотре нужен контракт предпросмотра v4 (коммит хоста 2d7944d10 или новее), а запуску UI-проектов на TSX в интерактивном предпросмотре нужен контракт предпросмотра v5 (коммит хоста 204a33ee5 или новее) и TypeScript Engine 0.7.0.

### Возможности

******

Возможности текущей предварительной версии:

- Визуальный дизайнер: файл скрипта и есть проект, реальный рендерер показывает дерево интерфейса по мере редактирования, структура / палитра компонентов / панель свойств охватывают все 55 компонентов, есть отмена / повтор и восстановление черновиков; экспортированный скрипт можно скопировать или сразу отправить в AutoJs6; перетаскивание на холст вставляет узел под указателем, открытые всплывающие окна рисуются внутри холста, Image показывает картинки @drawable и из папки изображений проекта, панель "Состояние" временно меняет значения предпросмотра state, а интерактивный предпросмотр выполняет скрипт проекта JavaScript в ограниченной песочнице (Android 8.0 или новее): нажатия и ввод обновляют холст так, как решает скрипт, а консоль показывает его вывод и ошибки; проекты бывают на JavaScript или TSX, TSX-проекты разбираются TypeScript Engine 0.7.0 или новее и сохраняются в каноническом виде TSX
- Связка с AutoJs6: проект можно отправить на выполнение, открыть в редакторе AutoJs6 (двусторонняя синхронизация), импортировать в каталог скриптов AutoJs6, скопировать или экспортировать; дизайнер также открывает файлы .js / .tsx прямо из редактора AutoJs6 или файлового менеджера и сохраняет в тот же файл; импортированный проект можно по запросу из меню редактора записать обратно в источник или заново импортировать из него
- Проекты UI (XML): дизайнер открывает и классические скрипты режима "ui" (макеты XML E4X) и правит их на месте, сохраняя каждый нетронутый байт (пробелы, комментарии, порядок атрибутов, кавычки, {выражения}); холст рисует служба предпросмотра AutoJs6 инфлейтером макетов режима ui (встроенные настоящие представления с Android 11, растровый снимок ниже), панель свойств следует каталогу тегов и атрибутов сайта документации, палитра перечисляет 48 тегов, элементу можно добавить заготовку обработчика `ui.<id>.on`, а панель привязок временно подменяет значения `{{ }}`
- Интерактивный предпросмотр проектов UI (XML) (1.7.0): при включенном переключателе "Взаимодействие" над холстом AutoJs6 выполняет весь скрипт как обычный запуск в режиме ui, холст показывает ui.layout скрипта и напрямую принимает касания, обработчики событий, привязки `{{ }}` и остальные модули работают по настоящей логике скрипта, а вкладка консоли показывает вывод, ошибки и причину завершения; скрипт перезапускается примерно через 0.4 с после правок, останавливается при выключении переключателя или выходе из дизайнера, а документ и файл не меняются
- XML-файлы макетов и проекты-папки (1.8.0): проекты UI могут хранить макеты в XML-файлах (ui.layoutFile, ui.inflate(files.read(...)), XML AutoJs6 или Android XML); проект с файлами макетов - это папка с main.js и project.json, которую можно экспортировать и импортировать как zip или папку и передать AutoJs6 для запуска или импорта как проект; Android XML правится по атрибутам, которые AutoJs6 действительно устанавливает
- UI-проекты на TSX и интерфейсы Compose (1.9.0): дизайнер редактирует JSX-макеты в ui.layout(...) скриптов .tsx (с заготовками событий, которые компилирует TypeScript), а AutoJs6 компилирует их с помощью TypeScript Engine для запуска в интерактивном предпросмотре; интерфейсы Compose, присоединенные к контейнерам <compose> через compose.attach, рисуются на холсте и редактируются на месте, а палитра добавляет контейнер вместе с вызовом за один шаг; в интерактивном предпросмотре диалоги скрипта рисуются внутри холста, скрытие дизайнера ставит скрипт на паузу вместо остановки, а скрипт, слишком долго занимающий главный поток, AutoJs6 останавливает
- Декларативный интерфейс: `compose.state` + `compose.mount(render)` автоматически перерисовывают интерфейс при изменении состояния, а долгоживущие дескрипторы узлов (`compose.Text({...})` и подобные) позволяют напрямую менять свойства и дочерние узлы
- Ядро Material 3: 29 фабрик узлов для компоновки, текста, значков, изображений, кнопок, ввода, выбора, ленивых списков, диалогов и индикаторов; Snackbar является командой сеанса, а не фабрикой compose.Snackbar
- Цепочки Modifier: `compose.modifier().padding(16).fillMaxWidth().background('#FFFFFF')` сохраняет порядок операций, а операции с ограниченной областью проверяются на стороне хоста
- Два способа отображения: `compose.mount` или вызов `compose` / `$compose` для активностей `"ui";`, и `compose.floaty` для плавающих окон raw или с изменяемым размером, в том числе из сценариев без UI
- Рендеринг внутри процесса хоста: обновления UI применяются в хосте, а события ставятся в очередь потока, которому принадлежит скрипт; рабочие потоки используют compose.post
- Один APK содержит arm64-v8a / armeabi-v7a / x86_64 / x86 без собственного нативного кода плагина; включена вспомогательная библиотека AndroidX graphics-path, сохраняются требования совместимости Android, хоста и плагина
- Нативное редактирование сохраняет выделение и композицию IME, поддерживает фокус и явные правки, отклоняет поздние правки поверх более нового ввода; переключатели и ползунки управляются скриптом
- Защита интеграции: проверки сообщают о недоступности отсутствующего или несовместимого плагина, ошибки используют `ComposeError`, а закрытие сессии или остановка сценария освобождает ее окна и обратные вызовы
- Пять исполняемых примеров: счетчик, проверка формы, список из 1000 элементов со стабильными ключами, плавающий HUD без режима UI и темы, с требованиями и индексом, синхронизированные с категорией примеров 3-Block Compose соответствующего хоста
- TSX поддерживает `<compose.Column>`, `<compose:Text>`, ссылки на фабрики узлов, фрагменты, слоты и реактивные обработчики; одно дерево не может смешивать Compose и прежние XML-узлы
- XML-контейнеры `<compose>` и compose.attach встраивают независимые сеансы Compose в UI-страницы или прежние плавающие окна; compose.AndroidView отображает готовый Android View либо результат синхронной фабрики
- compose.dialog возвращает обновляемый и закрываемый сеанс для диалогов и модальных нижних панелей в UI и обычных скриптах
- Расширенные компоненты Material 3: навигация и боковые панели, вкладки, нижние панели и меню, выбор даты и времени, страницы и сетки, чипы, значки, сегментированные и плавающие кнопки, поиск, подсказки и обновление жестом
- Галерея компонентов: запись в лаунчере показывает превью Material 3 и запускаемые примеры скриптов всех 55 компонентов, которые можно скопировать или отправить в AutoJs6; страница настроек по умолчанию следует языку, тёмной теме и цвету AutoJs6 и предлагает четыре значка лаунчера

### Использование

******

1. Установите соответствующую локальную сборку AutoJs6 с точкой входа compose (минимум 6.8.0 / 5322)
2. Установите APK плагина; откройте 3-Block Compose из лаунчера, чтобы попасть на главный экран дизайнера, создать проект скрипта или открыть галерею компонентов и настройки из верхней панели
3. Убедитесь в центре плагинов AutoJs6, что 3-Block Compose распознан и включён
4. Используйте `compose` или `$compose` в сценариях; монтируйте активности через `compose.mount`, либо разрешите хосту наложения и используйте `compose.floaty`
5. Меню редактора предлагает запуск, открытие в редакторе AutoJs6, импорт в скрипты AutoJs6, копирование и экспорт; выбор 3-Block Compose в меню редактора AutoJs6 (нужна сборка AutoJs6 с соответствующим обновлением) или в файловом менеджере редактирует файл скрипта напрямую

### Быстрый старт

******

Счетчик и плавающий HUD ниже работают с соответствующим локальным хостом предварительной версии. Перед запуском HUD разрешите хосту отображение поверх других приложений:

```js
"ui";

// Счётчик (декларативный слой render)
let count = compose.state(0);

compose.mount(() => compose.Column({ modifier: compose.modifier().fillMaxSize().padding(16), spacing: 12 }, [
    compose.Text({ key: 'counter', text: `Нажато ${count.value} раз`, style: 'headlineSmall' }),
    compose.Button({ key: 'inc', onClick: () => { count.value += 1; } }, 'Прибавить один'),
]));
```

```js
// Плавающий HUD (слой дескрипторов узлов)
let worker = null;
let status = compose.Text({ text: 'Подготовка...', color: '#FFFFFF' });
let win = compose.floaty(compose.Column({ padding: 12, bg: '#CC000000' }, [
    status,
    compose.TextButton({ contentColor: '#FFFFFF', onClick: () => win.close() }, 'Закрыть'),
]), { x: 50, y: 300, raw: true });
win.on('close', () => { if (worker) worker.interrupt(); });

worker = threads.start(() => {
    for (let i = 1; i <= 100; i++) {
        sleep(1000);
        compose.post(() => {
            if (!win.isClosed()) status.text = `Прогресс ${i}%`;
        });
    }
});
```

Пять исполняемых скриптов перечислены в assets/examples/index.json и синхронизированы с категорией 3-Block Compose соответствующего хоста. Заголовки описывают режим и разрешения. Сведения об узлах, модификаторах, темах, сеансах и окнах находятся в соответствующем локальном справочнике API и объявлениях TypeScript/редактора; сайт может еще не содержать эти локальные изменения.

### Совместимость

******

Требования к среде выполнения и ограничения плагина:

- Минимальная версия AutoJs6: 6.8.0 (5322) или новее; более старые хосты помечают плагин как несовместимый в центре плагинов
- Версия Android: 7.0 (API 24) или новее
- Архитектура процессора: arm64-v8a / armeabi-v7a / x86_64 / x86 (все четыре встроены в единый APK, выбирать сборку по архитектуре не нужно)
- Версия Compose: поставляется вместе с плагином (BOM 2026.09.00), не зависит от среды Compose хоста
- Версия контракта: 2; хост и плагин согласовывают версию контракта и при несовпадении отказывают в загрузке с понятной ошибкой
- Упакованным приложениям также требуется отдельно установленный совместимый плагин 3-Block Compose, с собственными настройками включения/авторизации приложения; проверяется встроенный runtime AutoJs6, а не versionCode самого приложения
- Фабрики View выполняются в главном потоке до отрисовки. Недопустимая замена сохраняет текущее содержимое; View не может принадлежать двум узлам или забираться у другого родителя. Его обработчики и ресурсы остаются под управлением вызывающего кода
- cancelable=false запрещает закрытие кнопкой назад, нажатием снаружи и смахиванием; явное закрытие и выход из скрипта освобождают диалог, сохраняя страницы и другие сеансы
- Эта сборка использует контракт 3-Block Compose V2 и требует AutoJs6 6.8.0 / 5322; для TSX нужен TypeScript Engine 0.6.7. Новые хосты поддерживают существующие компоненты старых рендереров V1; расширенным компонентам нужен V2
- compose.memo предоставляется AutoJs6 6.8.0 / 5323 и повторно использует фрагменты render с неизменными зависимостями; этот плагин обновлять не нужно, для TSX нужен TypeScript Engine 0.6.8
- Начиная с 1.2.0 классы контракта (org.autojs.plugin.compose.api) упаковываются с плагином для его автономного процесса; внутри AutoJs6 хост предоставляет те же классы, а копия плагина не используется
- Дизайнер работает в собственном процессе плагина и не зависит от AutoJs6; запуск, открытие в редакторе AutoJs6 и импорт в каталог скриптов AutoJs6 требуют установленного AutoJs6, а пункт меню редактора "Открыть в дизайнере 3-Block Compose" требует сборку AutoJs6, содержащую этот вход
- TSX-проектам дизайнера нужен TypeScript Engine 0.7.0 или новее (он предоставляет службу разбора в синтаксическое дерево), а при запуске AutoJs6 компилирует их через TypeScript Engine; без него или со старой версией TSX-проект открывается как исходный текст только для чтения, который можно просмотреть и скопировать
- Для выполнения скрипта в интерактивном предпросмотре дизайнера нужен Android 8.0 (API 26) или новее, так как Date в JavaScript песочницы построен на java.time; на более старом Android проект JavaScript показывается как проект TSX
- Предпросмотру макета проектов UI (XML) нужна сборка AutoJs6 6.8.0, содержащая службу предпросмотра (коммит хоста 306a8f7834 или новее; плагин проверяет наличие службы, а не номер версии); с Android 11 (API 30) холст встраивает настоящие представления, которые рисует AutoJs6, более старые версии показывают растровый снимок; без службы проект UI все равно можно править, а холст объясняет причину
- Интерактивному предпросмотру проектов UI (XML) нужна сборка AutoJs6 6.8.0 с контрактом предпросмотра v2 (коммит хоста 4c332c2053 или новее) и Android 13 (API 33) или новее; на Android 13 - 14 поля ввода на холсте не принимают клавиатуру, с Android 15 принимают; если условия не выполнены, переключатель скрыт, строка над холстом объясняет причину, а "Запустить в AutoJs6" остается; сборка AutoJs6 только с контрактом v1 по-прежнему дает предпросмотр макета
- Проекты UI с файлами макетов (1.8.0): предпросмотрам с файлами проекта (ресурсы res/, файлы макетов) нужна сборка AutoJs6 6.8.0 с контрактом предпросмотра v3 (коммит хоста 9df0a154b или новее), а запуску и импорту проектов-папок в AutoJs6 нужен коммит хоста faf412ef7 или новее; более старые сборки по-прежнему показывают предпросмотр XML-текста, а два назначения заменяются пояснением
- Новые возможности интерактивного предпросмотра (1.9.0): диалогам внутри холста, кнопке Назад, паузе и возобновлению, цветам строки состояния и пределу занятости главного потока нужна сборка AutoJs6 6.8.0 с контрактом предпросмотра v4 (коммит хоста 2d7944d10 или новее); запуску UI-проектов на TSX в интерактивном предпросмотре нужен контракт предпросмотра v5 (коммит хоста 204a33ee5 или новее) и TypeScript Engine 0.7.0 или новее; более старые сборки сохраняют поведение 1.8.0 (скрытие дизайнера останавливает скрипт, а возврат запускает его заново), а UI-проекты на TSX можно опробовать через "Запустить в AutoJs6"

### Частые вопросы

******

- Как запускаются примеры из галереи? "Запустить в AutoJs6" передаёт скрипт установленному AutoJs6; сама галерея только показывает превью и код и не выполняет скрипты
- Может ли дизайнер открыть любой скрипт? Он интерпретирует только объявления `compose.state` верхнего уровня и единственный вызов `compose.mount` / `floaty` / `dialog`; остальные операторы сохраняются как есть. Конструкции, которые нельзя сопоставить (корень не является фабрикой compose, несколько вызовов монтирования, функция отрисовки без return), отклоняются с указанием строки и столбца. В TSX-проектах теги `compose.X` / `compose:X` становятся редактируемыми узлами, прочие теги и выражения `{}` сохраняются как есть, а теги XML и атрибуты-развертки отклоняются
- Выполняет ли дизайнер скрипты? Только в интерактивном предпросмотре. При редактировании он лишь разбирает их (JavaScript парсером Rhino, TSX службой разбора TypeScript Engine) и показывает предпросмотр собственным рендерером плагина; обработчики событий не выполняются, а state показывает начальное значение или значение предпросмотра, заданное на панели "Состояние". При включенном "Взаимодействии" скрипт проекта JavaScript выполняется внутри плагина в ограниченной песочнице (Android 8.0 или новее): доступны только compose, console, toast и таймеры, нет доступа к классам Java / Android, файлам, сети и другим модулям AutoJs6, запуск дольше примерно 3 секунд останавливается, а результат меняет только холст, но не проект. Проект TSX (и любой проект на Android ниже 8.0) скрипт не выполняет: элементы, привязанные к state, меняют лишь значение предпросмотра. Настоящее выполнение остается за AutoJs6. Холст проекта UI (XML) служба предпросмотра AutoJs6 только размечает (создает и рисует представления), не выполняя скрипт проекта; значения `{{ }}` берутся из литеральных объявлений верхнего уровня скрипта (вычисленных в песочнице) или из переопределений на панели привязок. С 1.7.0 интерактивный предпросмотр проекта UI (XML) устроен иначе: при включенном переключателе AutoJs6 по-настоящему выполняет весь скрипт, точно как "Запустить в AutoJs6" (без ограничений песочницы, побочные эффекты действительно происходят, каждый проект один раз спрашивает подтверждение перед первым запуском), и на холсте показывается только содержимое его ui.layout; результат по-прежнему не записывается в проект; с 1.9.0 так же запускаются и UI-проекты на TSX (AutoJs6 сначала компилирует их с помощью TypeScript Engine)
- Почему нет `compose`? Глобальный объект предоставляет соответствующая локальная сборка хоста; установка только APK плагина его не добавляет
- Нужно ли удалять другие плагины интерфейса? Нет, 3-Block Compose не мешает существующему модулю `ui` и другим плагинам
- Что происходит при изменении плагина? Обновление, удаление или отключение закрывает активные сеансы и сообщает соответствующую ошибку; совместимый включенный плагин допускает новое монтирование
- Что требуется для плавающих окон? Разрешите хосту наложения и вызовите `window.requestFocus()` перед вводом текста. Если HyperOS не показывает окно, вернитесь на рабочий стол. Отсутствие разрешения возвращает PERMISSION_REQUIRED без автоматического открытия запроса
- Можно ли использовать TSX или любые функции Compose? TSX поддерживает документированные фабрики Compose с совместимым хостом и TypeScript Engine. Произвольные функции Kotlin Composable и пользовательские компоненты TSX не поддерживаются
- Теряется ли состояние при повороте? Текущий хост обрабатывает обычное изменение ориентации без замены движка скрипта. Реальное пересоздание или уничтожение Activity закрывает движок и его сеансы; бизнес-состояние автоматически не восстанавливается
- Как селекторы находят компоненты? testTag становится исходным ID без префикса пакета. id/testTag и desc/contentDescription различаются; текст Button может быть дочерним узлом, поэтому при необходимости поднимайтесь через parent() к кликабельному предку

### Разрешения и безопасность

******

Плагин не запрашивает разрешений времени выполнения Android и не обращается к сети, хранилищу или датчикам.

- Защита компонентов: Wake Activity и служба INFO защищены разрешением подписи `org.autojs.permission.PLUGIN`, поэтому доступ к ним есть только у хоста AutoJs6; редактор дизайнера является экспортируемым компонентом без разрешения, который принимает только Uri документа скрипта, переданный пользователем, а чтение и запись ограничены этим Uri
- Фоновое поведение: у плагина нет постоянной службы и запланированных задач, он получает только одну системную рассылку при своем обновлении, чтобы привести в порядок компоненты значка лаунчера; пока хост его не загрузил и не открыты ни дизайнер, ни галерея, он ничего не потребляет
- Граница данных: рендерер никогда не читает и не записывает данные скриптов и файлы пользователя, состояние интерфейса живет только в памяти процесса хоста; проекты и черновики дизайнера лежат в приватном каталоге плагина, импортируются и экспортируются только через системный выбор документов либо читают и записывают один файл скрипта по Uri, переданному пользователем; каталог проектов раскрывается только через собственный провайдер содержимого плагина, по запросу, при передаче проекта в AutoJs6; импорт сохраняет доступ к выбранному файлу, если поставщик это позволяет, но файл читается или записывается только когда пользователь выбирает "Записать обратно в источник" или "Повторно импортировать из источника"
- Песочница скриптов: интерактивный предпросмотр дизайнера выполняет скрипт проекта JavaScript внутри плагина интерпретатором Rhino. Доступны только compose, console, toast и таймеры; классы Java / Android, файлы, сеть и другие модули AutoJs6 недоступны, у каждого запуска есть пределы числа инструкций и времени, а результат используется только на холсте: проект не записывается
- Политика резервного копирования: резервное копирование приложения и перенос между устройствами отключены, и плагин не хранит данных, которые требовалось бы переносить
- Предпросмотр макета: холст проекта UI (XML) рисует установленный AutoJs6: плагин передает ему через службу предпросмотра AutoJs6 (защищенную подписным разрешением PLUGIN) только фрагмент XML и значения привязок, AutoJs6 создает представления инфлейтером макетов режима ui и рисует их обратно, не выполняет скрипт проекта и не имеет доступа к файлам проектов плагина; эта среда предпросмотра видна в списке запущенных скриптов AutoJs6 и может быть остановлена в любой момент; с 1.8.0 AutoJs6, который это поддерживает (контракт предпросмотра v3), также получает копию файлов проекта в zip только для чтения (проект-папку или папку res/ рядом с файлом скрипта), чтобы макет и запуск находили его ресурсы
- Интерактивный предпросмотр (проекты UI): при включенном переключателе плагин передает текст скрипта службе предпросмотра AutoJs6, и AutoJs6 выполняет его как обычный скрипт режима ui (тот же движок и те же разрешения скрипта, что и у "Запустить в AutoJs6", побочные эффекты действительно происходят), показывает на холсте только содержимое его ui.layout и возвращает вывод консоли; каждый проект один раз спрашивает подтверждение перед первым запуском, запуск виден в списке запущенных скриптов AutoJs6 и завершается при выключении переключателя, выходе из дизайнера или остановке из AutoJs6; скрипт не выполняется в процессе плагина, и плагин не расширяет его разрешения; с 1.9.0 AutoJs6 компилирует TSX-скрипты с помощью TypeScript Engine перед запуском и останавливает скрипт, занимающий главный поток дольше предела со страницы настроек
- Доступ к папкам и zip проектов (1.8.0): скрипт, открытый через контентный Uri, читает и записывает файлы макетов только в папке, которую пользователь выбрал в системном выборе папок и в которой проверено наличие скрипта (доступ на чтение и запись сохраняется только для этой папки); проекты-папки передаются AutoJs6 в виде zip через собственный поставщик контента плагина с разрешением на чтение для каждого запроса, и AutoJs6 распаковывает его, только проверив, что каждая запись остается внутри проекта

При загрузке рендерера хост сохраняет собственную модель разрешений для скриптов; плагин не расширяет системные возможности, доступные скриптам.

### Интерфейс плагина

******

Идентификаторы, доступные хосту:

```text
application id: io.github.supermonster003.autojs6.plugin.three.block.compose
plugin id: three-block-compose
engine: compose
variant: default
info action: org.autojs.plugin.INFO
info category: three-block-compose
renderer factory meta-data: org.autojs.plugin.compose.RENDERER_FACTORY
contract package: org.autojs.plugin.compose.api (version 2)
minimum host build: 5322 (6.8.0)
```

Хост обнаруживает плагин через `org.autojs.plugin.INFO` и читает сведения о возможностях, такие как `requiresHostVersion`; класс фабрики рендерера объявляется метаданными `org.autojs.plugin.compose.RENDERER_FACTORY`, а хост создаёт загрузчик классов из пути к APK плагина (с хостом в качестве родителя) и создаёт экземпляр внутри своего процесса.

Со старым AutoJs6 эти функции не появляются, и интерактивный предпросмотр работает как в 1.8.0 (скрытие дизайнера останавливает скрипт, а возврат запускает его заново); UI-проекты на TSX можно опробовать в AutoJs6 через "Запустить"

- `Новое` Интерактивный предпросмотр стал ближе к настоящему запуску: диалоги, открытые скриптом, показываются внутри холста и реагируют на нажатия; новая кнопка "Кнопка Назад" над холстом передает нажатие сначала открытому диалогу, затем событию back_pressed скрипта и завершает запуск, если ни один его не обработал; при скрытии дизайнера скрипт получает pause и продолжает работать, а при возврате получает resume вместо повторного запуска; цвета строки состояния и панели навигации, заданные скриптом, показываются полосами сверху и снизу холста
- `Новое` Новый параметр "Предел занятости главного потока" в группе "Дизайнер" страницы настроек (1 - 60 с, по умолчанию 5 с): если скрипт в интерактивном предпросмотре занимает главный поток AutoJs6 дольше этого (например, бесконечным циклом), AutoJs6 останавливает его, а строка показывается над холстом и в консоли, так что дизайнер не зависает
- `Новое` UI-макеты в TSX-скриптах: JSX-макеты в ui.layout(...) или ui.inflate(...) скрипта .tsx, начинающегося с "ui";, можно редактировать на холсте с той же палитрой, панелью свойств и вкладкой проблем, что и в UI-проектах на JS; неотредактированные макеты остаются как есть, отредактированные переписываются в едином формате; новый UI-проект может разместить макет "В TSX-скрипте"
- `Новое` Заготовки событий в TSX-макетах пишутся так, чтобы TypeScript их компилировал: нажатие становится onClick={() => { ... }} на элементе, для других событий добавляется (ui as any).<id>.on(...); UI-проекты на TSX по-прежнему передаются AutoJs6 файлами .tsx для запуска и экспорта
- `Новое` UI-проекты на TSX тоже работают в интерактивном предпросмотре: AutoJs6 сначала компилирует скрипт с помощью TypeScript Engine, и холст сообщает об этом; если компиляция не удалась, над холстом показывается первая ошибка с номером строки, а нажатие показывает все ошибки в консоли; номера строк ошибок во время запуска - это строки текста TSX
- `Новое` Интерфейсы Compose в UI-проектах можно редактировать напрямую: интерфейс, присоединенный к контейнеру <compose> через compose.attach(ui.<id>, ...), рисуется на холсте на месте контейнера, и его узлы можно выбирать; тогда панель переключается на панели Compose (свойства, слоты и состояние), "Назад к макету" возвращает к панелям макета, а во вкладке "Состояние" можно менять значения предпросмотра compose.state; эти правки делят историю отмены с макетом, а при сохранении переписывается только второй аргумент compose.attach, остальной скрипт не меняется
- `Новое` Новая категория "Compose" в палитре: за один шаг добавляет контейнер <compose> и его вызов compose.attach (в TSX-скриптах в форме, которую компилирует TypeScript), начальный интерфейс - Column с текстом, и сразу открывает его для редактирования; добавление можно отменить, в файл оно записывается только при сохранении
- `Исправление` На арабском "3-Block Compose" в заголовках главной страницы дизайнера и галереи и в текстах больше не показывается как "Block Compose-3"
- `Исправление` На арабском код в примерах галереи, а также в просмотре исходного кода, консолях, структуре и полях свойств дизайнера теперь располагается слева направо: точки с запятой больше не переносятся в начало строк, а длинные строки не обрезаются
- `Улучшение` "Различия предпросмотра" учитывают возможности установленного AutoJs6: с AutoJs6, поддерживающим контракт предпросмотра v4, диалоги, цвета строки состояния, события жизненного цикла и бесконечные циклы в главном потоке больше не перечисляются, а пояснение к ui.emitter теперь говорит, что предпросмотр получает только create, resume, pause и back_pressed
- `Улучшение` Контейнер <compose> без собственной высоты занимает в предпросмотре макета высоту своего интерфейса, и элементы под ним сдвигаются вниз, как при настоящем запуске
- `Зависимость` Обновление артефакта контракта ui-preview-api.aar до контракта предпросмотра ui v5 (v4 добавляет диалоги, события жизненного цикла, цвета окна и предел занятости главного потока, v5 добавляет запуск TSX и ошибки компиляции; сборки AutoJs6 только с v3 или старше сохраняют прежние предпросмотры)

- `Новое` "Сохранить как XML-файл" и "Новый XML-файл" в меню рядом с переключателем фрагментов: первый переносит в файл макет, написанный прямо в ui.layout(...) или ui.inflate(...), и переписывает вызов, второй добавляет файл с пустым корневым контейнером (XML AutoJs6 или Android XML) и строку ui.inflate в конце скрипта; оба отменяются и записывают файлы только при сохранении
- `Новое` Проекты-папки: личный проект, сохраненный с файлами макетов, становится папкой с main.js, файлами макетов и project.json, который принимает AutoJs6, поэтому AutoJs6 может запускать и упаковывать его как проект; новый проект UI тоже можно сразу создать такой папкой (шаблон XML AutoJs6 или Android XML); на главной проекты-папки показаны как "имя/"
- `Новое` Проекты-папки экспортируются одним zip, а меню главной импортирует zip и папки ("Импортировать скрипт или zip", "Импортировать папку")
- `Новое` "Запустить в AutoJs6" и "Импортировать в скрипты AutoJs6" передают AutoJs6 проект с файлами макетов в виде zip: AutoJs6 запускает его как проект из папки кэша, которая потом удаляется, или импортирует в папку с тем же именем и, если она уже есть, спрашивает, перезаписать ее или сохранить как новую папку
- `Новое` Скрипты, открытые из редактора AutoJs6, могут читать и записывать файлы макетов в своей папке: в первый раз выберите папку скрипта в системном выборе папок; доступ сохраняется
- `Новое` Макеты Android XML правятся в соответствии с тем, что AutoJs6 действительно поддерживает: панель свойств показывает настраиваемые атрибуты android: / app: каждого класса представления и параметры родительского макета, id записываются как @+id/..., палитра вставляет классы представлений Android, а вкладка проблем отмечает атрибуты, которые AutoJs6 игнорирует или не может установить
- `Новое` Вкладка проблем проектов UI перечисляет "различия предпросмотра": строки скрипта, которые в предпросмотре ведут себя иначе, чем в AutoJs6 (activity, ui.emitter, функции окна, диалоги, бесконечные циклы в главном потоке и другое), каждую с номером строки и пояснением; нажатие открывает документацию; ошибками они не считаются
- `Улучшение` Предпросмотр макета и интерактивный предпросмотр передают AutoJs6 файлы проекта, поэтому макеты могут использовать строки, цвета, размеры, стили, изображения и макеты `<include>` из res/, а ui.layoutFile работает в интерактивном предпросмотре (нужен контракт предпросмотра v3); со старым AutoJs6 вкладка проблем предупреждает, что предпросмотр может отличаться от реального запуска
- `Улучшение` Вставка элемента в контейнер, где есть только пробелы, больше не оставляет пустую строку
- `Зависимость` Обновлен артефакт контракта ui-preview-api.aar до контракта предпросмотра ui v3 (добавляет ключи запросов для ресурсов проекта вместе с макетом и для zip проекта вместе с запуском; сборки AutoJs6 только с v2 или v1 сохраняют прежние предпросмотры)

#### v1.7.0

_2026/10/15_

- `Подсказка` Интерактивный предпросмотр проектов UI (XML) теперь заставляет AutoJs6 по-настоящему выполнять весь скрипт (нужна сборка AutoJs6 6.8.0 с контрактом предпросмотра v2, коммит хоста 4c332c2053 или новее, и Android 13 или новее): побочные эффекты скрипта такие же, как при запуске в AutoJs6, и каждый проект один раз спрашивает подтверждение перед включением переключателя; если условия не выполнены, строка над холстом объясняет причину, а "Запустить в AutoJs6" остается
- `Новое` Интерактивный предпросмотр проектов UI (XML): при включенном переключателе "Взаимодействие" над холстом AutoJs6 выполняет весь скрипт как запуск в режиме ui, холст показывает ui.layout скрипта и напрямую принимает касания, а обработчики событий, привязки {{ }}, таймеры и остальные модули работают по настоящей логике скрипта; скрипт перезапускается примерно через 0.4 с после правок, останавливается при выключении переключателя, уходе дизайнера в фон или закрытии редактора, и холст возвращается к предпросмотру макета; документ, файл проекта и черновик никогда не меняются. На Android 13 - 14 поля ввода на холсте не принимают клавиатуру, с Android 15 принимают
- `Новое` Во время интерактивного предпросмотра вкладка консоли проекта UI показывает вывод скрипта, выполняемого AutoJs6 (с раскраской по уровню), состояние запуска и причину его завершения; при ошибке скрипта она (с номером строки) показывается над холстом, и касание открывает консоль; запуск виден под именем файла проекта в списке запущенных скриптов AutoJs6 и может быть остановлен оттуда
- `Исправление` Дизайнер иногда показывал "Служба предпросмотра AutoJs6 сейчас недоступна (at most 2 sessions per client)" при открытии проекта UI: когда размер холста менялся дважды до стабилизации макета, плагин дважды создавал сеанс предпросмотра в AutoJs6 и упирался в лимит сеансов на клиента; теперь одновременно создается один сеанс, а изменившиеся за это время размер или оформление применяются после
- `Зависимость` Обновлен артефакт контракта ui-preview-api.aar до контракта предпросмотра ui v2 (после v1 добавлены интерфейсы запуска и остановки скрипта и обратные вызовы консоли / ошибки / завершения; сборки AutoJs6 только с v1 по-прежнему дают предпросмотр макета)

### Сборка

******

После клонирования собирайте напрямую через Gradle Wrapper; версии Android Gradle Plugin и Kotlin автоматически выбирает плагин версий платформы в соответствии с текущим окружением IDE.

Собрать отладочный APK:

```powershell
.\gradlew.bat :app:assembleDebug
```

Запустить модульные тесты JVM и упаковать контрактные тесты для устройства:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

Собрать релизный APK (требуются `sign.properties` и ключ подписи):

```powershell
.\gradlew.bat :app:assembleRelease
```

Проверить подпись и получить релизный файл с суффиксом контрольной суммы:

```powershell
.\gradlew.bat :app:appendDigestToReleasedFiles
```

Проверить, что локализованные документы соответствуют исходникам:

```powershell
py .python\generate_markdown.py --check
```

Для сборки требуется JDK 21 или новее. После правки исходников в `.readme` или `.changelog` выполните `py .python\generate_markdown.py`, чтобы заново сгенерировать все документы.
