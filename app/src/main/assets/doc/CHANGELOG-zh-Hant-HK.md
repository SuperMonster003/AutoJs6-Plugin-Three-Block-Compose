# v1.9.0

###### 2026/10/22

* `提示` 1.9.0 的部分功能需要更新的 AutoJs6 6.8.0 構建: 互動預覽中的對話框, 返回鍵, 暫停與恢復, 狀態欄顏色和主線程佔用上限需要宿主提交 2d7944d10 之後 (預覽契約 v4); 在互動預覽中運行 TSX 腳本需要宿主提交 204a33ee5 之後 (預覽契約 v5), 並安裝 TypeScript Engine 0.7.0 或更高版本. AutoJs6 版本較舊時這些功能不出現, 互動預覽保持 1.8.0 的做法 (隱藏設計器即停止腳本, 回來時重新運行), TSX 的 UI 工程可以用 "運行" 在 AutoJs6 中試運行
* `提示` 編輯 TSX 腳本中的 UI 佈局需要 TypeScript Engine 0.7.0 或更高版本; 未安裝時這類工程只能查看源碼
* `新增` 互動預覽更接近真實運行: 腳本彈出的對話框顯示在畫布內, 可以直接點按; 畫布上方新增 "返回鍵" 按鈕, 依次交給對話框和腳本的 back_pressed 事件, 都不處理時結束運行; 隱藏設計器時腳本收到 pause 並繼續運行, 回來時收到 resume, 不再重新運行; 腳本設定的狀態欄與導航欄顏色顯示為畫布上下的色條
* `新增` 設定頁 "設計器" 分組新增 "主線程佔用上限" (1 - 60 秒, 預設 5 秒): 互動預覽中的腳本佔用 AutoJs6 主線程 (例如無限循環) 超過該時長時, AutoJs6 會停止它, 畫布上方與控制台顯示所在行, 設計器不會被卡住
* `新增` TSX 腳本中的 UI 佈局: 以 "ui"; 開頭的 .tsx 腳本裏寫在 ui.layout(...) 或 ui.inflate(...) 中的 JSX 佈局可以在畫布上編輯, 組件面板, 屬性抽屜與問題列表都與 JS 的 UI 工程相同; 沒有改動的佈局原樣保留, 改動過的佈局按統一格式重寫; 新建 UI 工程時佈局位置可選 "TSX 腳本內"
* `新增` TSX 佈局的事件樁採用能通過 TypeScript 編譯的寫法: 點擊寫成元素上的 onClick={() => { ... }}, 其它事件追加 (ui as any).<id>.on(...); TSX 的 UI 工程交給 AutoJs6 運行或匯出時仍是 .tsx 檔案
* `新增` TSX 的 UI 工程也能使用互動預覽: AutoJs6 先用 TypeScript Engine 編譯再運行, 編譯期間畫布上方顯示提示; 編譯失敗時顯示第一個錯誤的行號與說明, 點按可在控制台查看全部錯誤; 運行中報錯的行號就是 TSX 文本中的行號
* `新增` UI 工程中的 Compose 界面可以直接編輯: 用 compose.attach(ui.<id>, ...) 掛在 <compose> 容器上的界面畫在畫布上該容器的位置, 可以點選其中的節點; 選中後抽屜換成 Compose 的面板 (屬性, 插槽與狀態), "返回佈局" 回到佈局面板, 在狀態頁可以改 compose.state 的預覽值; 這些編輯與佈局共用撤銷歷史, 保存時只改寫 compose.attach 的第二個參數, 腳本其它部分不變
* `新增` 組件面板新增 "Compose" 分類: 一步添加 <compose> 容器和對應的 compose.attach 調用 (TSX 腳本中採用能通過編譯的寫法), 初始界面是一個含文字的 Column, 添加後直接打開以便編輯; 可撤銷, 保存時才寫入檔案
* `修復` 阿拉伯語界面中, 設計器首頁與組件畫廊的標題以及文字裏的 "3-Block Compose" 不再被排成 "Block Compose-3"
* `修復` 阿拉伯語界面中, 畫廊的示例代碼以及設計器的源碼, 控制台, 大綱與屬性欄裏的代碼改為從左到右排版, 不再出現分號跑到行首, 長行被截斷等問題
* `優化` "預覽差異" 按已安裝的 AutoJs6 實際支援的能力列出: 在支援預覽契約 v4 的 AutoJs6 上, 對話框, 狀態欄顏色, 生命週期事件與主線程上的無限循環不再列為差異, ui.emitter 的說明改為預覽中只會收到 create, resume, pause 與 back_pressed
* `優化` 沒有設定高度的 <compose> 容器在佈局預覽中按其界面的高度佔位, 下方的元素隨之下移, 與實際運行一致
* `依賴` 升級 ui-preview-api.aar 契約製品至 ui 預覽契約 v5 (v4 追加對話框, 生命週期事件, 窗口顏色與主線程佔用上限, v5 追加 TSX 運行與編譯錯誤; 只支援 v3 或更早版本的 AutoJs6 構建仍提供原有預覽)

# v1.8.0

###### 2026/10/16

* `提示` 1.8.0 的部分功能需要更新的 AutoJs6 6.8.0 構建: 預覽使用工程檔案 (res 資源, 佈局檔案) 需要宿主提交 9df0a154b 之後 (預覽契約 v3), 在 AutoJs6 中運行或匯入文件夾工程需要宿主提交 faf412ef7 之後; AutoJs6 版本較舊時設計器會提示並退回原有行為
* `新增` UI (XML) 工程的佈局可以寫在單獨的 XML 檔案中: 以字面量路徑調用 ui.layoutFile("...") 與 ui.inflate(files.read("...")), 可以是 AutoJs6 XML 或 Android 原生 XML (ui.useAndroidLayout); 設計器讀取並編輯這些檔案, 未改動的內容原樣保留, 片段切換器以檔案名列出它們
* `新增` 片段切換器旁的選單 "存為 XML 文件" 與 "新建 XML 文件": 前者把直接寫在 ui.layout(...) 或 ui.inflate(...) 中的佈局移到檔案並改寫調用, 後者新建只含一個空容器的檔案 (AutoJs6 XML 或 Android 原生 XML) 並在腳本末尾追加 ui.inflate 一行; 兩者都可撤銷, 保存時才寫入檔案
* `新增` 文件夾工程: 帶佈局檔案保存的私有工程變為文件夾 (main.js, 佈局檔案與 AutoJs6 認可的 project.json), 可在 AutoJs6 中作為項目運行與打包; 新建 UI 工程時也可以直接建立這樣的文件夾 (AutoJs6 XML 或 Android 原生 XML 模板); 首頁以 "名稱/" 顯示文件夾工程
* `新增` 文件夾工程可匯出為一個 zip, 首頁選單可匯入 zip 或文件夾 ("匯入腳本或 zip", "匯入文件夾")
* `新增` "在 AutoJs6 中運行" 與 "匯入 AutoJs6 腳本目錄" 把帶佈局檔案的工程以 zip 交給 AutoJs6: 運行時解壓到緩存目錄按項目運行, 結束後清理; 匯入時解壓到同名文件夾, 已存在時詢問覆蓋或另存為新文件夾
* `新增` 從 AutoJs6 編輯器打開的腳本可以讀寫同一文件夾中的佈局檔案: 第一次需要在系統文件夾選擇器中選擇腳本所在的文件夾, 之後保留授權
* `新增` Android 原生 XML 佈局按 AutoJs6 實際支援的屬性編輯: 屬性抽屜列出各控件類可設定的 android: / app: 屬性與父佈局的參數, id 寫作 @+id/..., 組件面板插入 Android 控件類, 問題列表提示 AutoJs6 會忽略或無法設定的屬性
* `新增` UI 工程的問題列表單列 "預覽差異": 腳本中在預覽裏與在 AutoJs6 中運行行為不同的寫法 (activity, ui.emitter, 窗口級函數, 對話框, 主線程上的無限循環等), 每條帶行號與說明, 點按打開文檔, 不計入錯誤數
* `優化` 佈局預覽與互動預覽把工程檔案交給 AutoJs6, 佈局可以引用 res 中的字串, 顏色, 尺寸, 樣式, 圖片與 `<include>` 佈局, 互動預覽中的 ui.layoutFile 也能正常運行 (需要預覽契約 v3); AutoJs6 版本較舊時問題列表提示預覽可能與實際運行不同
* `優化` 向只含空白的容器插入元素時不再留下空行
* `依賴` 升級 ui-preview-api.aar 契約製品至 ui 預覽契約 v3 (追加隨佈局交出工程資源與隨運行交出工程 zip 的請求鍵; 只有 v2 或 v1 的 AutoJs6 構建仍提供原有預覽)

# v1.7.0

###### 2026/10/15

* `提示` UI (XML) 工程的互動預覽現在由 AutoJs6 真實運行整份腳本 (需要包含預覽契約 v2 的 AutoJs6 6.8.0 構建, 宿主提交 4c332c2053 之後, 以及 Android 13 或更高版本): 腳本的副作用與在 AutoJs6 中運行相同, 每個工程首次打開開關時會先確認; 不滿足條件時畫布上方說明原因, 可改用 "在 AutoJs6 中運行"
* `新增` UI (XML) 工程的互動預覽: 打開畫布上方的 "互動預覽" 開關後, AutoJs6 把整份腳本當作一次 ui 模式運行來執行, 畫布顯示腳本的 ui.layout 並直接接收點擊與觸摸, 事件處理函數, {{ }} 綁定, 定時器與其它模組都按腳本邏輯真實運行; 修改工程後約 0.4 秒重新運行, 關閉開關, 設計器轉到後台或關閉編輯頁時停止, 畫布回到佈局預覽; 文檔, 工程檔案與草稿都不會被改動. Android 13 - 14 上畫布中的輸入框收不到鍵盤輸入, Android 15 起可以
* `新增` UI 工程的 "控制台" 頁在互動預覽期間顯示 AutoJs6 運行腳本的輸出 (按等級着色), 運行狀態與結束原因; 腳本出錯時畫布上方顯示錯誤 (帶行號), 點擊打開控制台; 運行以工程檔名出現在 AutoJs6 的運行列表中, 也可以從那裡停止
* `修復` 設計器打開 UI 工程時偶爾顯示 "AutoJs6 預覽服務現在不可用 (at most 2 sessions per client)" 的問題: 畫布尺寸在佈局穩定前變化兩次時, 插件會向 AutoJs6 重複建立預覽會話, 觸到每個客戶端的會話上限; 現在同一時間只建立一個會話, 期間的尺寸與外觀變化隨後補上
* `依賴` 升級 ui-preview-api.aar 契約製品至 ui 預覽契約 v2 (在 v1 之後追加運行與停止腳本的接口和控制台 / 錯誤 / 結束回調; 只有 v1 的 AutoJs6 構建仍可提供佈局預覽)

# v1.6.0

###### 2026/10/15

* `提示` 設計器新增 UI (XML) 工程: 可以打開與編輯傳統 "ui" 模式腳本 (E4X XML 佈局), 畫布由 AutoJs6 繪製. 佈局預覽需要包含預覽服務的 AutoJs6 6.8.0 構建 (宿主提交 306a8f7834 之後), Android 11 (API 30) 起畫布嵌入 AutoJs6 繪製的真實視圖, 更低版本顯示位圖快照; 沒有該服務時仍可編輯, 畫布說明原因
* `新增` 設計器支持 UI (XML) 工程: 新建工程時可選 "UI (XML)", 導入或從 AutoJs6 編輯器 / 檔案管理器打開 "ui" 模式腳本也按 UI 工程讀取; 首頁列表以 JS / TSX / UI 標註工程類型. 腳本中的 XML 佈局以帶位置的語法樹保存, 未觸碰的部分 (空白, 註釋, 屬性順序, 引號, {表達式}) 逐字節保留, 只有被編輯的開始標籤, 文字與新插入的元素會被改寫; 腳本裡的其他 XML 字面量也能切換到畫布編輯
* `新增` UI 工程的編輯頁: 大綱 (摺疊, 上下移, 刪除, 長按拖拽, 多個佈局時切換), 屬性抽屜 (標籤, id, 文字內容, 已設定的屬性與按 View 類別分組的目錄屬性, 文字 / `{{ }}` 綁定 / {表達式} 三態, 裸屬性, 任意屬性名), 組件面板 (文檔的 48 個標籤, 按分類列出並帶預設屬性), 綁定值面板 (`{{ }}` 名稱的求值結果與臨時覆蓋, 只影響畫布), 問題列表 (按文檔站的標籤與屬性目錄校驗) 與控制台 (AutoJs6 繪製佈局時報告的診斷); 保存, 草稿恢復, 來源同步, 發送運行, 在 AutoJs6 編輯器中打開, 導入 AutoJs6 腳本目錄, 複製與匯出對 UI 工程同樣可用
* `新增` UI 工程的畫布由 AutoJs6 繪製 (佈局預覽): 插件把 XML 片段與綁定值交給 AutoJs6 的預覽服務, AutoJs6 用 ui 模式的佈局器建立真實視圖並畫回畫布, 不運行工程的腳本; 點選與拖拽在畫布上照常工作, 繪製失敗時定位到出錯的元素; 預覽運行時以 "3-Block Compose 預覽" 出現在 AutoJs6 的運行列表中, 可從那裡停止
* `新增` UI 工程的屬性抽屜可以為選中元素添加事件: 在 ui.layout 調用之後追加一段 `ui.<id>.on('事件', ...)` 處理函式樁 (元素沒有 id 時自動補一個), 處理邏輯在腳本編輯器中編寫; 腳本已註冊的事件顯示為 "腳本中已處理"
* `依賴` 附加 ui-preview-api.aar 契約製品 (AutoJs6 ui 佈局預覽契約 v1), 供設計器請求 AutoJs6 繪製 UI 工程的畫布

# v1.4.0

###### 2026/10/13

* `提示` 設計器的 TSX 工程需要 TypeScript Engine 0.7.0 或更高版本; 未安裝或版本過低時, TSX 工程只能以唯讀源碼方式查看與複製
* `新增` 設計器支援 TSX 工程: 新建工程時可選 JavaScript 或 TSX, 也可以匯入 .tsx 檔案, 或從 AutoJs6 編輯器與檔案管理器直接打開 .tsx 檔案; TSX 源碼由 TypeScript Engine 解析後在畫布中編輯, 儲存為統一格式的 TSX (4 空格縮排, 單引號屬性, 每個子元素一行); 設計器無法編輯的寫法 (例如別名標籤, 條件或循環生成的子元素) 按原文保留, XML 標籤與展開屬性等無法表示的寫法會拒絕打開並指出行列
* `新增` 設計器中 TSX 工程的 "運行" 會把工程檔案交給 AutoJs6, 由 TypeScript Engine 編譯後運行; 有未儲存的修改時先儲存
* `新增` TypeScript Engine 未安裝, 版本過低或解析服務暫時不可用時, 設計器以唯讀方式顯示 TSX 工程的源碼並說明原因, 可以複製源碼或重試; 安裝或更新 TypeScript Engine 後回到設計器會自動重試
* `修復` 設計器儲存無法寫回的外部腳本時, 檔名含空格, 括號等工程名稱不允許的字元會使插件閃退, 而不是另存為工程的問題; 現在這些字元換成 "-" 後另存, 匯入腳本也按同一規則命名
* `優化` TSX 工程中編輯事件處理函數時由 TypeScript Engine 檢查語法, 可以使用類型標註等 TypeScript 寫法
* `依賴` 附加 typescript-parser-api.aar 契約製品 (TypeScript 語法樹解析契約 v1), 供設計器讀取 TSX 工程
